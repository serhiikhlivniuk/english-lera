# Lera's English

Воркспейс для Лери (11 клас, підготовка до НМТ). Зроблений з тієї ж основи, що й english-workspace для Andrii — структура, скрипти і формат даних однакові.

Відмінності від english-workspace:

- репозиторій `english-lera` → сайт `https://serhiikhlivniuk.github.io/english-lera/`;
- префікси localStorage свої (`lera:v1:`, `lera:theme`, `lera-l01:`) — обидва сайти на одному домені github.io, і без цього прогрес учнів змішувався б у твоєму браузері;
- Supabase той самий проєкт, але `studentId: "Lera"` — рядки не перетинаються з Andrii;
- план уроку для вчителя лежить поруч з уроком: `lessons/lesson-01-teacher.html` (посилання є на teacher.html).

Статичний сайт-воркспейс для занять англійською: уроки, словник, граматика,
корисні посилання, домашка і постійне посилання на Google Meet.

Жодного білда й фреймворків — чистий HTML/CSS/JS. Увесь контент лежить у `data/*.json`,
сторінки його просто рендерять. Щоб щось додати — редагуєш JSON і робиш коміт.

## Структура

```
index.html          головна: найближче заняття, статистика, домашка
lessons.html        список уроків
vocabulary.html     словник + картки + квіз
grammar.html        правила по темах + міні-квізи
speaking.html       розмовні блоки на кожен урок
links.html          корисні посилання
homework.html       домашка з чекбоксами
teacher.html        сторінка вчителя: прогрес учня (немає в меню — відкривається за прямим лінком)
lessons/            окремі сторінки уроків (самодостатній HTML)
data/               увесь контент: config, lessons, vocabulary, grammar, links, homework
assets/             app.css, app.js, store.js, lesson-sync.js, wordgrab.js
supabase.sql        схема БД для збереження прогресу
```

## Деплой на GitHub Pages

1. Створити репозиторій `english-lera` і залити ці файли:

```bash
git init
git add .
git commit -m "English workspace"
git branch -M main
git remote add origin https://github.com/serhiikhlivniuk/english-lera.git
git push -u origin main
```

2. Settings → Pages → Source: **Deploy from a branch**, branch `main`, folder `/ (root)`.
3. Через хвилину сайт буде на `https://serhiikhlivniuk.github.io/english-lera/`.

Файл `.nojekyll` вимикає Jekyll (щоб нічого не ламалось), `robots.txt` і `<meta name="robots" content="noindex">`
закривають сайт від пошуковиків — знайти його можна тільки за посиланням.

## Мова інтерфейсу

Увесь сайт англійською — це частина навчання. Українська лишилася тільки як підказка:
кнопка **UA** у шапці показує/ховає переклади слів і прикладів. Вибір запамʼятовується
в браузері учня. Технічно це один CSS-клас `.uk-tr` — усе, що в нього загорнуте,
зникає, коли перемикач вимкнено.

У словнику головне значення — англійське визначення (поле `def`), український
еквівалент (`uk`) іде другим рядком під перемикачем. Квіз і картки тренують
слово ↔ визначення, без переходу через українську.

Цей README лишається українською — він для тебе, не для учня.

## Що заповнити перед стартом

У `data/config.json`:

- `meet.url` — постійне посилання на Google Meet (уже вписане);
- `meet.schedule` — дні й час (уже стоїть Monday 17:30 і Friday 17:00);
- `student` — імʼя учня;
- `supabase` — див. нижче.

## Збереження прогресу

Без налаштувань усе працює на `localStorage`: галочки в домашці, позначені слова
й результати квізів живуть у браузері учня. Сайт при цьому не можна зламати.

Щоб бачити прогрес учня в `teacher.html`:

1. Створити безкоштовний проєкт на [supabase.com](https://supabase.com).
2. SQL Editor → вставити вміст `supabase.sql` → Run.
3. Settings → API → скопіювати **Project URL** і **anon public** ключ.
4. Вписати їх у `data/config.json`:

```json
"supabase": { "url": "https://xxxx.supabase.co", "anonKey": "eyJhbGci...", "studentId": "student-1" }
```

Анонімний ключ публічний за задумом — він лежить у коді сайту. Захист тримається на
RLS-політиках зі `supabase.sql`: можна писати прогрес і читати його, але не більше.
Персональних даних у базі немає — тільки галочки й бали.

> Безкоштовний проєкт Supabase засинає після тижня без запитів. Два заняття на тиждень
> його будять, але якщо буде довга пауза — просто зайти в дашборд і натиснути Restore.

## Сторінка вчителя

`teacher.html` навмисне не стоїть у навігації — відкривається за прямим посиланням
`.../teacher.html`. Показує: скільки пунктів домашки виконано, які слова ще не позначені
вивченими, результати квізів і що учень вписав у завданнях аркуша уроку.

Аркуші уроків (`lessons/*.html`) самі зберігають відповіді учня локально, а скрипт
`assets/lesson-sync.js` дублює їх у спільне сховище — звідти вони й потрапляють у Supabase.
Щоб новий урок теж синхронізувався, додай перед `</body>` його сторінки:

```html
<script src="../assets/store.js"></script>
<script src="../assets/lesson-sync.js" data-lesson="lesson-03"></script>
```

і на `<html>` атрибут `data-base="../"`.

## Три речі, які варто знати про контент

**Практика в граматиці.** У кожної теми є короткий квіз (`quiz`, 3–6 питань) і
окремий банк тренування (`practice`, по 10 питань). У практиці після кожної
відповіді показується пояснення з поля `why` — тому воно обовʼязкове для
кожного питання.

**Speaking.** `data/speaking.json` — один блок на урок: `warmup`, `main`
(`task`, `howto`, `prompts`), `phrases`, `followup`, плюс `teacher` — підказка
для тебе, яка на сторінці не показується учневі окремо. Поле `grammar` — список
id тем, вони стають клікабельними чіпами.

**Правило всередині вправи.** У сторінках уроків блоки `<details class="gbox">`
генеруються з `data/grammar.json`, а не пишуться руками. Якщо змінив правило в
JSON — перегенеруй ці блоки, інакше текст у вправі розійдеться з розділом
граматики.

**Слова від учня.** `assets/wordgrab.js` дає кнопку «Add to my words» на
виділений текст. Слова лягають у ключ `vocab:mine` разом із реченням, звідки
взяті. Вони зʼявляються в учня в розділі Vocabulary і в тебе на сторінці
вчителя у блоці inbox — звідти їх треба переносити в `data/vocabulary.json`
руками, з нормальним визначенням.

## Кеш після оновлення

GitHub Pages віддає css і js із кешем на ~10 хвилин, тому після заливки учень
може ще якийсь час бачити стару версію. Щоб цього не було, посилання на власні
файли мають версію: `assets/app.js?v=1`.

**Після кожної зміни в `assets/` підніми цифру** — `?v=2`, `?v=3` — одразу в усіх
html-файлах. Тоді браузер вважає це новим файлом і тягне свіжий. Для `data/*.json`
цього не треба: вони й так запитуються з `cache: 'no-cache'`.

## Як додавати контент

- **Новий урок**: покласти HTML у `lessons/`, додати обʼєкт у `data/lessons.json`.
  Сторінка уроку має містити: `<html lang="en" data-base="../">`, смугу `.ew-back`,
  `<script src="../assets/store.js?v=1">` і `<script src="../assets/lesson-sync.js?v=1" data-lesson="lesson-0N">`.
  Перевір, що активна вкладка НЕ має атрибута `hidden` — інакше сторінка відкриється порожньою.
- **Слова**: дописати в `data/vocabulary.json` (`word`, `pos`, `def`, `uk`, `example`, `lesson`).
  `def` — англійське визначення, `uk` — переклад-підказка.
- **Граматика**: новий обʼєкт у `data/grammar.json` — `rules`, `mistakes`, `quiz`.
- **Посилання**: `data/links.json`, тип `video` / `article` / `practice` / `tool`.
- **Домашка**: `data/homework.json`, новий блок зверху масиву.

Дрібні правки можна робити просто у веб-інтерфейсі GitHub — натиснути олівець,
змінити текст, Commit. Через хвилину сайт оновиться.
